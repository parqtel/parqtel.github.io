How it works

From application to answer

Ingestion, storage, querying, and alerting run in one process. MCP servers run separately.

  1. Send your signals

    Your OpenTelemetry SDK or Collector sends metrics, logs, and traces to Parqtel over gRPC or HTTP.

  2. Buffer and persist

    A live buffer makes data queryable. A write-ahead log protects writes, and data is flushed into compressed Parquet blocks.

  3. Explore and investigate

    Use the console, supported Prometheus queries, Grafana, or MCP tools to inspect your telemetry.

Before you start

Start locally, deploy deliberately

Review network access and memory requirements before running a shared instance.

Parqtel has no built-in authentication. Keep it on a trusted network. Its in-memory buffer is unbounded, so size memory for your workload. Read the limitations →
Quick Start

Running in under a minute

Docker

docker run -d \
  --name parqtel \
  -p 8080:8080 \
  -p 4317:4317 \
  -v parqtel_data:/data \
  ghcr.io/parqtel/parqtel-oss:0.3.1

curl http://localhost:8080/health   # {"status":"ok"}
curl http://localhost:8080/ready    # {"status":"ready"}

Docker Compose or from source

make dev-setup          # copies .env, starts stack
# → Parqtel :9090 · Grafana :3000 · Prometheus :9091

# or from source
cargo build --release && ./target/release/parqtel serve
