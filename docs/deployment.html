Deployment

From a single container to production Kubernetes — Parqtel deploys anywhere a Linux binary or OCI image runs.

Docker (single container)

A 4-stage build: a cargo-chef planner, dependency cook, binary build, then a gcr.io/distroless/cc-debian12:nonroot runtime (~15 MB, no shell).

docker build -t parqtel:local .
docker run -d \
  --name parqtel \
  -p 8080:8080 \
  -v parqtel_data:/var/lib/parqtel \
  -e PARQTEL__STORAGE__DATA_DIR=/var/lib/parqtel/data \
  -e PARQTEL__LOGS__DATA_DIR=/var/lib/parqtel/logs \
  -e PARQTEL__TELEMETRY__LOG_FORMAT=json \
  parqtel:local

docker exec parqtel curl -f http://localhost:8080/health

Homebrew (Linux & macOS)

The compiled release binary — no Docker, no Rust toolchain. Updated automatically on every release.

brew tap parqtel/tap
brew install parqtel-oss
parqtel serve

Docker Compose (full stack)

Includes Parqtel, Grafana (auto-provisioned), Prometheus (self-monitoring), and a load generator. Network isolation splits frontend (user-facing) and backend (internal, no egress).

ServicePortDescription
parqtel9090Main observability server
grafana3000Dashboards
prometheus9091Self-monitoring scraper
load-generator—Synthetic data
mcp-*3001–3007MCP servers (opt-in)
ℹ

MCP servers are commented out by default. Add tokens to .env and uncomment the services (or use a gitignored docker-compose.override.yml for local secrets).

cp .env.example .env      # add MCP tokens if needed
docker compose up -d
make dev-setup            # first-time onboarding shortcut

Kubernetes (Helm)

The chart at charts/parqtel is production-grade: HPA, PDB, NetworkPolicy, Ingress, ServiceMonitor, and PrometheusRule. Each MCP server is deployable as its own pod.

helm install parqtel charts/parqtel \
  --namespace parqtel --create-namespace \
  -f charts/parqtel/ci/full-values.yaml

Common values:

replicaCount: 3
resources:
  requests: { cpu: 500m, memory: 512Mi }
  limits:   { cpu: 2000m, memory: 2Gi }
persistence: { enabled: true, size: 50Gi, storageClass: gp3 }
autoscaling:
  enabled: true
  minReplicas: 2
  maxReplicas: 10
  targetCPUUtilizationPercentage: 70
networkPolicy: { enabled: true }
mcp:
  slack: { enabled: true, env: { SLACK_BOT_TOKEN: "xoxb-..." } }

CI value overlays ship for minimal, default, and full installs and pass helm lint with the bundled values.schema.json. Local k3d workflows are wired through make local-k3d-up.

systemd (bare metal)

For a plain Linux host, install the release binary and the unit file at deploy/systemd/parqtel.service.

sudo cp target/release/parqtel /usr/local/bin/
sudo useradd -r -s /bin/false parqtel
sudo mkdir -p /var/lib/parqtel/{data,logs} /etc/parqtel
sudo chown -R parqtel:parqtel /var/lib/parqtel
sudo cp config/default.toml /etc/parqtel/parqtel.toml
sudo cp deploy/systemd/parqtel.service /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now parqtel

Production recommendations

Storage

Prefer SSDs (Parquet loves fast sequential reads). Size for (ingest_rate × retention_days) / compression_ratio — typically 10–20× with Zstd.

Memory

The block index is held in memory and scales with block count. 512 MB minimum; 2 GB for high-cardinality workloads.

Networking

Terminate TLS at a reverse proxy (nginx/envoy). Use /health for load-balancer probes and match max_body_size to your proxy.

Monitoring

Scrape /metrics. Watch parqtel_ingest_total, parqtel_query_duration_seconds, parqtel_blocks_total, parqtel_compaction_duration_seconds.

Backup

Blocks are immutable once written — safe to copy live. Back up index.bin for fast recovery; otherwise it rebuilds from Parquet.

Supply chain

Images are Trivy-scanned, cosign-signed, and tracked by OpenSSF Scorecard. Pull from GHCR with signature verification.

Parqtel

Ultra-lightweight SRE observability engine — streaming OTel signals into compressed Parquet.
