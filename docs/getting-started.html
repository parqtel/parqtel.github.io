Getting Started

From zero to a queryable metric, log and trace — about fifteen minutes. These instructions track release v0.3.1 (October 2026).

↗

Parqtel ships as a single binary and an OCI image published to GitHub Container Registry (ghcr.io/parqtel/parqtel-oss), multi-arch for linux/amd64 and linux/arm64. There is no Docker Hub mirror.

1 · Install

Docker (recommended)

docker run -d \
  --name parqtel \
  -p 8080:8080 \
  -p 4317:4317 \
  -v parqtel_data:/data \
  ghcr.io/parqtel/parqtel-oss:0.3.1

curl http://localhost:8080/health    # {"status":"ok"}
curl http://localhost:8080/ready     # {"status":"ready"}

/health is a static liveness check. /ready actually reads block-index metadata and returns 503 when the storage path is unusable — use it for Kubernetes readiness and load-balancer health checks.

Homebrew (Linux & macOS)

brew tap parqtel/tap
brew install parqtel-oss
parqtel --version

The formula pulls the release binary from the parqtel-oss GitHub releases (linux/amd64, linux/arm64, darwin/amd64, darwin/arm64) — no local Rust toolchain required.

From source

Minimum supported Rust version (MSRV) is 1.87.

git clone https://github.com/parqtel/parqtel-oss.git
cd parqtel-oss
cargo build --release          # target/release/parqtel
./target/release/parqtel serve

Docker Compose (full stack)

Brings up Parqtel, Grafana, Prometheus (scraping Parqtel) and a load generator. MCP servers are present but commented out.

make dev-setup        # copies .env.example → .env, then docker compose up -d
# or manually:
cp .env.example .env
docker compose up -d
ℹ

Compose publishes Parqtel on :9090 (HTTP) and :4317 (OTLP gRPC), Grafana on :3000, Prometheus on :9091. A plain docker run uses :8080.

2 · Send your first metric

Parqtel speaks OTLP. Point any OpenTelemetry SDK at :4317 (gRPC) or :8080 (HTTP), or post OTLP/JSON directly:

curl -X POST http://localhost:8080/v1/metrics/json \
  -H "Content-Type: application/json" \
  -d '{
  "resourceMetrics": [{
    "resource": {"attributes": [
      {"key": "service.name", "value": {"stringValue": "my-web-app"}}]},
    "scopeMetrics": [{
      "metrics": [{
        "name": "http_requests_total",
        "sum": {"isMonotonic": true, "dataPoints": [{
          "asDouble": 1,
          "timeUnixNano": "'$(date +%s%N)'",
          "attributes": [
            {"key": "method", "value": {"stringValue": "GET"}},
            {"key": "status", "value": {"stringValue": "200"}}]}]}}]}]}]}'
⚠

OTLP/JSON attributes must be an array of {"key": …, "value": {"stringValue": …}} objects — a plain object map is rejected. Instantly querying a point you just sent only works if its timestamp is inside the 5-minute lookback window (query.lookback_delta_ns).

3 · Logs and traces

# Log record
curl -X POST http://localhost:8080/v1/logs/json \
  -H "Content-Type: application/json" \
  -d '{
  "resourceLogs": [{
    "resource": {"attributes": [
      {"key": "service.name", "value": {"stringValue": "my-web-app"}}]},
    "scopeLogs": [{"logRecords": [{
      "timeUnixNano": "'$(date +%s%N)'",
      "severityText": "INFO",
      "body": {"stringValue": "User logged in successfully"},
      "attributes": [{"key": "user_id", "value": {"stringValue": "user_123"}}]}]}]}]}'

# Server span — this also derives traces_service_{requests,errors,duration_ms}_total
curl -X POST http://localhost:8080/v1/traces/json \
  -H "Content-Type: application/json" \
  -d '{
  "resourceSpans": [{
    "resource": {"attributes": [
      {"key": "service.name", "value": {"stringValue": "my-web-app"}}]},
    "scopeSpans": [{"spans": [{
      "traceId": "5b8efff798038103d269b633813fc60c",
      "spanId": "eee19b7ec3c1b174",
      "name": "GET /checkout",
      "kind": 2,
      "startTimeUnixNano": "'$(date +%s%N)'",
      "endTimeUnixNano": "'$(date +%s%N)'",
      "status": {"code": 2}}]}]}]}'

4 · Query it back

# Instant PromQL (5-minute lookback)
curl "http://localhost:8080/api/v1/query?query=http_requests_total"

# Range PromQL
curl "http://localhost:8080/api/v1/query_range?query=rate(http_requests_total[5m])&start=$(date -d '1 hour ago' +%s)&end=$(date +%s)&step=60"

# Logs (ParqtelQL boolean grammar)
curl "http://localhost:8080/api/v1/logs?filter=severityText%3D'INFO'"

# Spans
curl "http://localhost:8080/v1/traces/search?service=my-web-app&limit=20"

# Correlation across signals
curl "http://localhost:8080/v1/correlate?trace_id=5b8efff798038103d269b633813fc60c"

Open http://localhost:8080/ui for the built-in console — an Overview dashboard, a PromQL query builder, log facets, a trace-grouped browse list with waterfall, and an alert stream with an Evidence tab.

5 · Verify durability

Parqtel acknowledges a write once the row is in the write-ahead log, not once the Parquet block is on disk. Crash loss is therefore bounded by ingest.wal_sync_interval_ms (default 1 s) rather than a whole block window, and whatever the WAL still holds is replayed on startup.

docker exec parqtel healthcheck ready      # bundled probe binary: liveness|ready
curl -s localhost:8080/api/v1/stats | jq   # blocks, rows, disk bytes, index size per signal
curl -s localhost:8080/metrics | grep parqtel_flush | head
↗

Read Durability & recovery for the commit ordering, replay behaviour and tuning, and Storage engine for the block and pruning model.
