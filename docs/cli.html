CLI Reference#

The Parqtel binary provides a small command surface: start the server, inspect storage, and export metric data to CSV. A compact subcommand also exists, but it is currently a no-op stub (see below).

↗

There is no WAL replay, rebuild, or recover command. Recovery happens automatically at startup. If Parqtel does not come up correctly, the problem is in your configuration or storage — not a missing maintenance step.

Synopsis#

parqtel [OPTIONS] [COMMAND]

Running parqtel with no command is equivalent to parqtel serve.

Options#

OptionShortEnvironment variableDescription
--config <PATH>-cPARQTEL_CONFIGPath to the TOML configuration file.
--bind <ADDRESS>-bPARQTEL_BINDTCP bind address. Overrides server.bind_address.
--data-dir <PATH>-dPARQTEL_DATA_DIRData directory. Overrides storage.data_dir and logs.data_dir.
--log-level <LEVEL>—RUST_LOGLog level override.
--help-h—Print help.
--version-V—Print version.

Commands#

CommandDescription
serveStart the HTTP server. This is the default when no command is given.
compactNo-op stub in v0.3.1 — logs and exits without compacting.
inspectPrint a metrics-and-logs storage summary as JSON.
exportExport metric data to CSV (output must live inside the data directory).

serve#

Starts the Parqtel server: OTLP ingestion, the query API, the alerting loop, the retention sweeper, and the embedded console.

parqtel serve

# With overrides
parqtel --config /etc/parqtel/parqtel.toml --bind 0.0.0.0:9090 serve

# Point at a different data directory
parqtel -d /var/lib/parqtel/data serve
SettingDefault
HTTP listen address0.0.0.0:8080
OTLP gRPC listen address0.0.0.0:4317
Embedded consolehttp://<bind-address>/ui

serve handles SIGTERM and SIGINT with a graceful shutdown, waiting up to server.shutdown_timeout_secs (default 30) for in-flight requests.

compact#

⚠

⚠ This command does nothing in v0.3.1. It prints Running one-off compaction... and exits successfully without running a pass. Background compaction still runs automatically inside serve; do not rely on the CLI for maintenance.

parqtel compact          # prints a message and exits; no work is done

For reference, the background compactor that serve runs applies these rules:

BehaviourDetail
Merge triggerTwo or more blocks with fewer than 10,000 rows.
Tiered passBlocks older than 6 hours and under 500,000 rows.
Maximum source blocks per mergestorage.compaction_max_merge_blocks (default 12).
Maximum merges per passstorage.compaction_max_merges_per_pass (default 8).
Signals coveredMetrics and logs. Traces are not compacted.

That pass runs every compaction_interval_secs (default 3600) while serve is running.

inspect#

Prints a storage summary as JSON and exits. Useful for inventory scripts, capacity checks, and verifying a restore.

parqtel inspect
parqtel inspect -d /var/lib/parqtel/data | jq

The output is a JSON object with metrics and logs sections only — trace blocks live in a traces/ subdirectory and are not included. Each section has block count, total rows, total bytes, and (for metrics) the metric-name list.

The equivalent over HTTP, which reports all three signals, is:

curl -s http://localhost:8080/api/v1/stats | jq

export#

Exports metric data to CSV.

↗

The output path must resolve inside storage.data_dir. This is a path traversal guard. A relative filename like requests.csv resolves outside the data directory and fails with Output path must be within data directory. Write under the data directory and move the file afterwards.

parqtel export \
  --metric http_requests_total \
  --start 2026-10-01T00:00:00Z \
  --end 2026-10-02T00:00:00Z \
  --output data/exports/requests.csv
OptionShortDescription
--metric <NAME>—Metric to export. Required.
--start <RFC3339>—Start timestamp, RFC 3339 format. Required.
--end <RFC3339>—End timestamp, RFC 3339 format. Required.
--output <PATH>-oOutput file path, inside the data directory. Required.
# Export and inspect
parqtel export \
  --metric traces_service_requests_total \
  --start 2026-10-01T00:00:00Z \
  --end 2026-10-01T06:00:00Z \
  --output data/exports/red.csv

head -5 data/exports/red.csv

Exit behaviour#

SituationBehaviour
Configuration invalidExits non-zero, printing all validation errors together.
Write-ahead log cannot be openedExits non-zero rather than running without crash protection.
Data directory unusableExits non-zero.
serve receives SIGTERM/SIGINTGraceful shutdown within shutdown_timeout_secs.

Troubleshooting#

SymptomCauseResolution
parqtel compact appears to do nothingIt is a no-op stub in v0.3.1.Nothing to fix — background compaction runs inside serve.
inspect reports zero blocksWrong data directory, or retention has expired everything.Confirm with -d / --data-dir; note inspect omits traces.
export fails with "Output path must be within data directory"The path escapes storage.data_dir.Write under the data directory (for example data/exports/out.csv).
export returns no rowsThe window contains no data, or the metric name is wrong.Verify the metric exists with /api/v1/label/__name__/values and widen the range.
Server exits immediately after startA configuration error.Read the full error output; every invalid key is listed at once.
Server exits but logs are emptyStartup failed before logging was initialised.Re-run with --log-level debug.
No command available to rebuild the indexRecovery is automatic.The index reconciles itself at startup; see Backup, Restore & Upgrade.
