Configuration

Parqtel resolves configuration through Figment in a fixed priority order. Every key below is validated at startup, and everything here maps 1:1 to a struct in parqtel-core/src/config/.

Layering

Highest priority first:

  1. CLI flags — --config, --bind, --data-dir, --log-level
  2. Environment variables — PARQTEL__ prefix, __ as the nested separator
  3. TOML config file — config/default.toml, or the path from --config / PARQTEL_CONFIG
  4. Built-in defaults
ℹ

The documented PARQTEL__SECTION__KEY spelling works as written — it was previously ignored because the prefix parser left an empty first key segment. The single-underscore form (PARQTEL_SECTION_KEY) also works.

[server]

KeyTypeDefaultDescription
bind_addressString"0.0.0.0:8080"TCP address to listen on. Cannot be empty.
grpc_bind_addressString"0.0.0.0:4317"OTLP gRPC listener; empty string disables.
max_connectionsInteger1024Maximum simultaneous TCP connections.
shutdown_timeout_secsInteger30Seconds to wait for in-flight requests during graceful shutdown.
flush_interval_secsInteger5Background tick that checks whether a block has reached its duration. Bounds how late a duration-triggered flush can be — not how often blocks are written.
alert_interval_secsInteger15Seconds between alert-rule evaluation cycles.
retention_interval_secsInteger3600Seconds between retention sweeps. Lower it if a sweep visibly stalls endpoints; raise it on very large indexes.
grpc_concurrency_limitInteger64Maximum concurrent OTLP exports per gRPC connection. Without it one client can monopolise the ingest mutex that HTTP exporters also queue on.
index_persist_interval_secsInteger2How often the block-index sidecar is written. Mutations mark it dirty and are batched, so this bounds how long a block can sit in memory before the sidecar catches up. Lower it if you restart often.

[storage] — metrics and traces

Traces have no configuration block of their own; they reuse [storage] entirely. Full detail in the storage page.

KeyTypeDefaultDescription
backendString"parquet"Only "parquet" is registered.
data_dirPath"data"Metric and trace blocks, the metrics sidecar, and both WALs.
block_duration_secsInteger7200Time span of a single block.
max_rows_per_blockInteger1000000Row cap. Also the pre-check that flushes before a batch would exceed it.
compressionString"zstd"zstd · snappy · lz4 · none.
compression_levelIntegerunsetzstd 1–22. Unset uses the codec default. Rejected for the other codecs rather than silently ignored. Lower levels encode faster and compress less — use a low level for frequently rewritten blocks.
retention_daysInteger7Retention for metrics and traces.
compaction_interval_secsInteger3600Interval between compaction passes; floored at 60 s.
row_group_sizeInteger100000Must be > 0 and ≤ max_rows_per_block. This is what row-group pruning depends on — a too-large value silently costs query time, which is why it is validated.
compaction_max_merge_blocksInteger12Max source blocks merged into one compacted block. Too few and the small-block population grows faster than compaction removes it.
compaction_max_merges_per_passInteger8Max merges one cycle performs, across all signals. Bounds the disk I/O a single cycle can take.

[logs]

Same shape as [storage] minus backend, with these defaults: data_dir = "data/logs", block_duration_secs = 1800, max_rows_per_block = 200000, row_group_size = 20000, retention_days = 3. Validation delegates to the same shared rule set, so the two blocks cannot drift apart.

[ingest]

KeyTypeDefaultDescription
max_body_sizeInteger10485760Maximum request body size (10 MB). Applied to both axum's default body limit and a request-body-limit layer, and used to derive gRPC message limits, so HTTP and gRPC cannot disagree.
wal_enabledBooleantrueWAL for metrics and traces. Bounds crash loss to the sync interval instead of the whole block window. A WAL that cannot be opened fails startup. Also gates the background flush worker.
log_wal_enabledBooleantrueWAL for logs.
wal_sync_modeString"interval"none (write only — survives a process crash, not machine loss) · interval (periodic fsync) · always (fsync per record).
wal_sync_interval_msInteger1000fsync period in interval mode. Clamped to a 1 ms floor.
wal_max_segment_bytesInteger67108864Size at which the WAL rolls to a new segment (64 MiB).
max_inflight_flushesInteger4Max block encodes in flight for the background flush worker, which also bounds its queue. A full queue encodes inline, so backpressure degrades to synchronous. Requires wal_enabled.
rotator_shardsInteger4Metrics writer shards, clamped 1–256. Shards merge into one block, so block count, query fan-out and durability are unchanged; it costs one writer buffer per shard. Raise only where parqtel_ingest_lock_wait_seconds shows real contention.

See Durability & recovery for the commit protocol these knobs participate in.

[alerts.presets]

Built-in alert packs embedded in the binary at compile time. Pack keys: kubernetes, coredns, external-secrets, service-red, parqtel.

KeyTypeDefaultDescription
modeString"auto"auto (activate a pack when its canary metrics appear) · all (activate every selected pack at startup) · off (never load built-ins).
includeList or comma-separated string[]Include-only pack keys. Wins over exclude when both are set (a warning is logged). Unknown keys are logged and ignored.
excludeList or comma-separated string[]Pack keys to skip; applied only when include is empty.

Activation is insert-if-absent, and once activated a pack never deactivates — so a rule from rules_dir, or a disable/delete via the API, always wins over the built-in.

export PARQTEL__ALERTS__PRESETS__MODE=auto
export PARQTEL__ALERTS__PRESETS__INCLUDE=kubernetes,parqtel
export PARQTEL__ALERTS__PRESETS__EXCLUDE=service-red

CLI

parqtel [OPTIONS] [COMMAND]

Options:
  -c, --config <PATH>      Path to TOML config file  [env: PARQTEL_CONFIG]
  -b, --bind <ADDRESS>     TCP bind address          [env: PARQTEL_BIND]
  -d, --data-dir <PATH>    Data directory            [env: PARQTEL_DATA_DIR]
      --log-level <LEVEL>  Log level override        [env: RUST_LOG]
  -h, --help                 Print help
  -V, --version              Print version

Commands:
  serve    Start the HTTP server (default)
  compact  Run one compaction pass and exit
  inspect  Print a storage summary as JSON
  export   Export metric data to CSV
            --metric <NAME> --start <RFC3339> --end <RFC3339> --output <PATH>

There is no WAL, replay or index-rebuild CLI command — recovery happens automatically at startup.

Alert rule YAML

One rule per --- document under rules_dir, loaded non-recursively:

id: http-error-rate-high          # unique, stable — the alert instance prefix
name: HTTP error rate high
signal: metrics                   # metrics | logs | traces (default: metrics)
query: "rate(http_errors_total[5m])"
condition:
  type: threshold                 # only "threshold" is implemented
  operator: ">"                  # > >= < <= == !=
  value: 0.5                     # errors/sec — tune to your traffic profile
  for_duration_secs: 300         # must hold this long before Pending → Firing
severity: critical               # critical | warning | info
labels:
  team: platform
annotations:
  summary: "HTTP error rate above 0.5/sec"
  runbook: "https://wiki.example.com/runbooks/http-errors"
enabled: true
noise_suppression_threshold: 0.7  # 0.0-1.0, higher = more suppression

The evaluation loop parses each enabled rule's query, executes it over a trailing query.lookback_delta_ns window, and thresholds the last sample of every result series — one alert instance per series, fingerprinted by id plus the series' labels. Two consequences:

  1. No cross-metric arithmetic. A rule query is a single selector with an optional aggregation. Ratios such as errors / requests cannot be expressed — threshold absolute rates or window counts instead.
  2. histogram_quantile is unavailable in alert rules: the alert loop uses the query plan path, not the AST engine that powers interactive queries. Use _sum rate proxies for latency-style rules.

Recording rules

name: http:requests:rate5m
expression: "rate(http_requests_total[5m])"
interval_secs: 60
labels:
  aggregation: "recording_rule"

Pipelines

name: nginx-access-logs
enabled: true
stages:
  - name: parse
    type: preprocessor
    config:
      pattern: '$remote_addr - $remote_user [$time_local] "$request" $status $body_bytes_sent'
  - name: extract_metrics
    type: metric_extractor
    config:
      metrics:
        - name: nginx_requests_total
          type: counter
          value_field: status

Validation

Everything is checked at startup, and all errors are reported together:

Error: server.bind_address cannot be empty;
       storage.compression must be one of: zstd, snappy, lz4, none;
       storage.row_group_size must be within 1..=1000000 (max_rows_per_block);
       telemetry.log_format must be 'text' or 'json';
       ingest.tail_sampling.sampling_ratio must be within [0.0, 1.0]

Note what is rejected rather than silently accepted: a row_group_size of 0 or above max_rows_per_block (which would disable row-group pruning), and a compression_level set for a codec that ignores it.
