Configuration

Parqtel resolves configuration through Figment in a fixed priority order: defaults → TOML file → environment variables → CLI flags.

CLI commands

CommandDescription
parqtel serveStart the HTTP server (default)
parqtel compactRun one compaction pass and exit
parqtel inspectPrint a storage summary as JSON
parqtel exportExport metric data to CSV (--metric, --start, --end, --output)
 
parqtel --config config/default.toml serve
parqtel export --metric http_requests_total \
  --start 2025-01-01T00:00:00Z --end 2025-01-02T00:00:00Z \
  --output out.csv

Layering

  1. Built-in defaults
  2. TOML config file — config/default.toml, override with PARQTEL_CONFIG
  3. Environment variables — PARQTEL__ prefix, __ as the nested separator (e.g. PARQTEL__STORAGE__COMPRESSION)
  4. CLI flags — highest priority

Sample config

The TOML file mirrors the PARQTEL__* env surface. Equivalent nested keys:

bind = "0.0.0.0:8080"
data_dir = "data"

[storage]
data_dir = "data"
logs_dir = "data/logs"
compression = "zstd"        # zstd | snappy | lz4
retention_days = 7
logs_retention_days = 3

[query]
max_series = 500
max_samples_per_series = 5000

[telemetry]
log_format = "json"         # json | text
↗

See the canonical config/default.toml in the repository for the full, versioned schema.

Alerting

Alerts are defined as YAML rules evaluated by a background loop (every 15s). Rules support threshold and anomaly detection and flow through a state machine: Inactive → Pending → Firing → Resolved, with noise scoring to cut alert fatigue.

route: demo
rules:
  - name: high_error_rate
    expr: rate(http_requests_total{status="500"}[5m]) > 0.05
    for: 2m
    severity: critical
    annotations:
      summary: "Error rate above 5% for {{ $labels.service }}"

Manage rules at runtime via /api/v1/rules (GET/POST/PUT/DELETE) and acknowledge/resolve via /api/v1/alerts/:id/.... See the API reference.
