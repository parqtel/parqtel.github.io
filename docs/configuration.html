Configuration Reference#

Every configuration key Parqtel accepts, with its type, default, and behaviour. This page is a lookup reference — for task-oriented walkthroughs see Deploy, Ingest Telemetry, and Alerting.

Everything here is validated at startup. If a value is invalid, Parqtel refuses to start and reports all problems together rather than failing on the first one.

Overview#

Parqtel can be configured with a TOML file, environment variables, or CLI flags. All three feed the same settings; only the precedence differs.

Configuration layering#

Higher entries override lower ones.

PrioritySourceExample
1CLI flags--bind 0.0.0.0:9090
2Environment variablesPARQTEL__SERVER__BIND_ADDRESS
3TOML filebind_address = "0.0.0.0:8080" in the config file
4Built-in defaults0.0.0.0:8080

Environment variable naming#

The prefix is PARQTEL__ and the nested separator is __:

export PARQTEL__SERVER__BIND_ADDRESS="0.0.0.0:9090"
export PARQTEL__STORAGE__RETENTION_DAYS=14

The single-underscore form (PARQTEL_SERVER_BIND_ADDRESS) also works.

↗

A note on history. In releases before v0.3.0, the documented double-underscore spelling was silently ignored because of a prefix-parsing defect — every environment-variable example in the documentation had no effect. This was fixed in v0.3.0. If you are upgrading from an older release and had "working" environment overrides, verify they are actually applied after upgrading.

[server]#

KeyTypeDefaultDescription
bind_addressString"0.0.0.0:8080"TCP address to listen on. Cannot be empty.
grpc_bind_addressString"0.0.0.0:4317"OTLP gRPC listener. An empty string disables it.
max_connectionsInteger1024Maximum simultaneous TCP connections.
shutdown_timeout_secsInteger30Seconds to wait for in-flight requests during graceful shutdown.
flush_interval_secsInteger5How often to check whether a block has reached its duration. Bounds how late a duration-triggered flush can be.
alert_interval_secsInteger15Seconds between alert-rule evaluation cycles.
retention_interval_secsInteger3600Seconds between retention sweeps. Lower it if a sweep visibly stalls endpoints; raise it on very large indexes.
grpc_concurrency_limitInteger64Maximum concurrent OTLP exports per gRPC connection. Without it, one client can monopolise the ingest path that HTTP exporters also queue on.
index_persist_interval_secsInteger2How often the block index sidecar is written. Lower it if you restart often.

[storage] — metrics and traces#

Traces have no configuration block of their own; they reuse [storage] entirely.

KeyTypeDefaultDescription
backendString"parquet"Only parquet is registered.
data_dirPath"data"Metric and trace blocks, the metrics sidecar, and both write-ahead logs.
block_duration_secsInteger7200Time span of a single block (2 hours).
max_rows_per_blockInteger1000000Row cap. Also the pre-check that flushes before a batch would exceed it.
compressionString"zstd"One of zstd, snappy, lz4, none.
compression_levelIntegerunsetZstd level 1–22. Unset uses the codec default. Validated regardless of codec; only applied when compression = "zstd" and ignored by snappy, lz4, and none.
retention_daysInteger7Retention for metrics and traces.
compaction_interval_secsInteger3600Interval between compaction passes; floored at 60s.
row_group_sizeInteger100000Must be > 0 and ≤ max_rows_per_block. This is what row-group pruning depends on.
compaction_max_merge_blocksInteger12Maximum source blocks merged into one compacted block.
compaction_max_merges_per_passInteger8Maximum merges one cycle performs, across all signals.

[logs]#

Same shape as [storage] minus backend.

KeyTypeDefaultDescription
data_dirPath"data/logs"Log blocks, log sidecar, and the log write-ahead log.
block_duration_secsInteger1800Time span of a single log block (30 minutes).
max_rows_per_blockInteger200000Row cap.
compressionString"zstd"One of zstd, snappy, lz4, none.
compression_levelIntegerunsetZstd level 1–22.
retention_daysInteger3Log retention.
compaction_interval_secsInteger3600Interval between compaction passes.
row_group_sizeInteger20000Rows per row group.
compaction_max_merge_blocksInteger12Maximum source blocks per merge.
compaction_max_merges_per_passInteger8Maximum merges per cycle.

Validation delegates to the same rules as [storage], so the two cannot drift apart.

[ingest]#

KeyTypeDefaultDescription
max_body_sizeInteger10485760Maximum request body size (10 MB). Applied to both the framework default and an explicit body-limit layer, and used to derive gRPC message limits — so HTTP and gRPC cannot disagree.
wal_enabledBooleantrueWrite-ahead log for metrics and traces. Bounds crash loss to the sync interval instead of the whole block window. A log that cannot be opened fails startup. Also gates the background flush worker.
log_wal_enabledBooleantrueWrite-ahead log for logs.
wal_sync_modeString"interval"none (write only — survives a process crash, not machine loss), interval (periodic sync), always (sync per record).
wal_sync_interval_msInteger1000Sync period in interval mode. Clamped to a 1ms floor.
wal_max_segment_bytesInteger67108864Size at which the log rolls to a new segment (64 MiB).
max_inflight_flushesInteger4Maximum block encodes in flight for the background flush worker. A full queue encodes inline, so backpressure degrades to synchronous. Requires wal_enabled.
rotator_shardsInteger4Metrics writer shards, clamped 1–256. Shards merge into one block, so block count, query fan-out, and durability are unchanged; it costs one writer buffer per shard. Raise only where parqtel_ingest_lock_wait_seconds shows real contention.

See Durability & Recovery for the commit protocol these knobs participate in.

[ingest.tail_sampling]#

KeyTypeDefaultDescription
keep_errorsBooleantrueKeep traces containing error-status spans.
slow_trace_msIntegerunsetKeep traces whose server spans exceed this duration. Unset disables the rule.
sampling_ratioFloat1.0Fraction of remaining traces to keep (0.0–1.0, validated).
per_serviceTable{}Per-service overrides; each entry fully replaces the global policy for that service.

[query]#

KeyTypeDefaultDescription
max_seriesInteger1000Maximum time series returned per query. Truncates silently.
max_samples_per_seriesInteger10000Maximum samples per series. Truncates silently.
timeout_secsInteger30Query execution timeout; also applied as an HTTP middleware timeout.
lookback_delta_nsInteger300000000000Instant-query lookback in nanoseconds (5 minutes, the Prometheus default). Alert evaluation uses the same window.

[telemetry]#

KeyTypeDefaultDescription
log_levelString"info"Log filter: trace, debug, info, warn, error.
log_formatString"text"text or json. Anything else fails validation.
otlp_enabledBooleanfalseExport Parqtel's own traces and SLI metrics over OTLP.
otlp_endpointString"http://127.0.0.1:4317"Collector endpoint. http:// selects plaintext, https:// selects TLS.
otlp_trace_levelString"info"Minimum span level exported — independent of log_level, so trace export survives a raised console level.

profiling_enabledBooleanfalseEnable the /debug/pprof/* endpoints; they return 404 while disabled. Restrict them with a NetworkPolicy.
profiling_frequencyInteger99CPU sampling frequency in Hz (1–1000).
⚠

When otlp_enabled = true but the OTLP exporter fails to initialise — an unreachable collector, for example — Parqtel logs a warning and continues with console logs only. Ingestion is never blocked by self-telemetry.

[alerts.presets]#

Built-in alert packs. Pack keys: kubernetes, coredns, external-secrets, service-red, parqtel.

KeyTypeDefaultDescription
modeString"auto"auto activates a pack when its canary metrics appear; all activates every selected pack at startup; off never loads built-ins.
includeList or comma-separated string[]Include-only pack keys. Wins over exclude when both are set. Unknown keys are logged and ignored.
excludeList or comma-separated string[]Pack keys to skip. Applied only when include is empty.

Activation is insert-if-absent, and once activated a pack never deactivates — so a rule from rules_dir, or a disable/delete through the API, always wins over a built-in.

export PARQTEL__ALERTS__PRESETS__MODE=auto
export PARQTEL__ALERTS__PRESETS__INCLUDE=kubernetes,parqtel
export PARQTEL__ALERTS__PRESETS__EXCLUDE=service-red

Environment variables#

Any configuration key can be set as an environment variable using PARQTEL__SECTION__KEY.

# Server
export PARQTEL__SERVER__BIND_ADDRESS="0.0.0.0:9090"
export PARQTEL__SERVER__GRPC_BIND_ADDRESS="0.0.0.0:4317"
export PARQTEL__SERVER__MAX_CONNECTIONS=2048
export PARQTEL__SERVER__FLUSH_INTERVAL_SECS=10
export PARQTEL__SERVER__RETENTION_INTERVAL_SECS=1800
export PARQTEL__SERVER__INDEX_PERSIST_INTERVAL_SECS=5

# Storage
export PARQTEL__STORAGE__DATA_DIR="/var/lib/parqtel/data"
export PARQTEL__STORAGE__COMPRESSION="zstd"
export PARQTEL__STORAGE__COMPRESSION_LEVEL=1
export PARQTEL__STORAGE__RETENTION_DAYS=14
export PARQTEL__STORAGE__BLOCK_DURATION_SECS=3600

# Row-group pruning only works when the row group fits inside a block.
export PARQTEL__STORAGE__ROW_GROUP_SIZE=50000

# Ingest and sampling
export PARQTEL__INGEST__MAX_BODY_SIZE=20971520
export PARQTEL__INGEST__WAL_SYNC_MODE=always
export PARQTEL__INGEST__TAIL_SAMPLING__SAMPLING_RATIO=0.1

Alert rule YAML#

One rule per --- document under rules_dir, loaded non-recursively:

id: http-error-ratio-high         # unique, stable — the alert instance prefix
name: HTTP error ratio high
signal: metrics                   # accepted; only metrics is evaluated today
query: "http_error_ratio"         # a gauge your app or Collector exports
condition:
  type: threshold                 # only "threshold" is implemented
  operator: ">"                   # > >= < <= == !=
  value: 0.05
  for_duration_secs: 120
severity: warning                 # info | warning | critical
labels:
  team: platform

The evaluation loop loads each enabled rule's selector over a trailing query.lookback_delta_ns window and thresholds the newest raw sample of every result series — one alert instance per series, fingerprinted by id plus the series' labels.

Two consequences worth knowing:

  • Range functions and aggregations are not applied. In v0.3.1 the alert loop builds its plan without a step, so rate(), increase(), sum(), and histogram_quantile() parse but do not change the value being thresholded. Composed queries such as sum(rate(...)) can match no series at all. Alert on gauges whose current value is the signal, or precompute rates and ratios before ingestion. Recording rules are stored and not executed in v0.3.1.
  • Malformed or unmatched queries are skipped silently. Check that the bare selector returns series with GET /api/v1/query?query=<selector> before relying on the rule.

Full guide: Alerting.

Recording rules#

↗

Stored, not executed. Definitions are validated and stored through POST /api/v1/recording_rules, but no ruler scheduler evaluates them in v0.3.1, so no derived series is written.

Groups are Prometheus-style. Through the API a request body is a single group:

name: http_service_aggregations
interval: 1m
rules:
  - record: service:http_error_rate:rate5m
    expr: |
      sum by (service_name) (rate(http_requests_total{status=~"5.."}[5m]))
        / sum by (service_name) (rate(http_requests_total[5m]))
    labels:
      aggregation: "rate5m"
    description: "HTTP 5xx error rate per service"
    retention_override_days: 90

A file uses the same group shape under a top-level groups: list.

Pipelines#

↗

Stored, not executed. Definitions are validated and stored through POST /api/v1/pipelines, but no ingest-stage processor runs them in v0.3.1, so they do not transform data or extract metrics.

name: nginx-access-logs
description: Parse Nginx access logs
match:
  signal: logs
  conditions:
    - field: service_name
      op: "="
      value: "nginx"
stages:
  - type: processor
    name: parse_nginx_log
    processor: regex_extract
    source_field: body
    pattern: '^(?P<method>[A-Z]+) (?P<path>\S+) HTTP/[\d.]+" (?P<status>\d+)'
    target_fields:
      http.method: method
      http.target: path
      http.status_code: status
    on_parse_failure: keep_original
  - type: metric_extract
    name: extract_request_count
    metric_name: nginx_requests_total
    metric_type: counter
    value_field: "constant:1"
    dimensions: [http.method, http.status_code, service_name]

Validation#

Everything is checked at startup and all errors are reported together:

Error: server.bind_address cannot be empty;
storage.compression must be one of: zstd, snappy, lz4, none;
storage.row_group_size (2000000) must not exceed storage.max_rows_per_block (1000000);
telemetry.log_format must be 'text' or 'json';
ingest.tail_sampling.sampling_ratio must be within [0.0, 1.0]

Note what is rejected rather than silently accepted:

Rejected valueWhy
row_group_size = 0Would disable row-group pruning — a silent performance regression.
row_group_size > max_rows_per_blockSame reason.
compression_level outside 1–22Out of range for zstd. Note it is validated even when the codec ignores it; an in-range level is simply ignored by snappy, lz4, and none.
wal_enabled = true but the log cannot be openedStartup fails rather than running without crash protection.

Troubleshooting#

SymptomCauseResolution
Parqtel refuses to start with a config errorA key is outside its valid range.Read the error list; each line names the offending key.
An environment variable has no effectWrong spelling, or you are on a version before v0.3.0 where the double-underscore form was ignored.Use PARQTEL__SECTION__KEY; upgrade if needed.
A rule file is ignoredYAML parse error, or the file is in a subdirectory.rules_dir is loaded non-recursively. Validate the YAML.
Queries truncate unexpectedlyquery.max_series or query.max_samples_per_series.Compare totalSeriesCount against returned series; raise the limit or aggregate.
Alerts evaluate over the wrong windowUsing an old version with a hardcoded window.Upgrade to v0.3.0+, where alerts honour query.lookback_delta_ns.
