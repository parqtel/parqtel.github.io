Release Notes#

What changed in each Parqtel release, written from the perspective of someone running it. Internal build and pipeline changes are described only where they affect what you can configure or rely on.

The current release is v0.3.1 (5 October 2026). Releases follow semantic versioning; the CHANGELOG in the repository is the authoritative record.

Upgrade paths at a glance#

FromToIn-place upgrade?Notes
v0.2.0v0.3.x✅ YesBlocks stay readable; rolling back is safe.
v0.3.0v0.3.1✅ YesNo format or API changes; the metrics WAL now defaults to on.
Pre-v0.2.0 (arrow2-era format)v0.2.0+❌ NoThe Parquet encoding changed. Wipe the data directory.
AnyEarlier✅ YesBlocks are self-describing Parquet and older binaries read them.

Full procedure: Back Up, Restore & Upgrade.

v0.3.1 — Chart and release pipeline#

5 October 2026 · No format or API changes.

This release is mostly about making Helm deployments and published releases work correctly. The on-disk format and HTTP/gRPC surface are unchanged from v0.3.0; the one runtime default that did change is the metrics write-ahead log, now on.

Fixed#

  • Helm chart: write-ahead log settings are now honoured. wal_max_segment_bytes and wal_sync_interval_ms were previously not rendered into the configuration, so there was no way to tune write-ahead log segment size or sync interval without hand-editing a ConfigMap that the next helm upgrade would discard. Both are now rendered and settable.

Changed#

  • Kubernetes probes are now configurable. livenessProbe, readinessProbe, and startupProbe were hardcoded. This matters more than it sounds: on start, Parqtel replays whatever the write-ahead log did not flush, and that replay is proportional to unflushed log size — so startup is slowest exactly when the pod is least healthy. The old hardcoded startup budget was 150 seconds, and an install restarting with a large write-ahead log could exceed it, be killed mid-replay by the liveness probe, and restart with an even larger log. Defaults reproduce the previous values exactly, so upgrading changes nothing until you edit them. Each probe can be set to {} to disable it.
  • The metrics write-ahead log is now on by default, matching logs. It previously defaulted to off, which is the wrong default for a product that acknowledges writes over HTTP: without it, a crash loses up to a whole block window and the ingest path degrades to synchronous flushing. Still overridable via ingest.wal_enabled.

v0.3.0 — Second public beta#

4 October 2026

Features#

  • Built-in alert preset packs. Five packs — kubernetes, coredns, external-secrets, service-red, and parqtel — ship inside the binary (the rule files are named kubernetes-cluster.yaml and parqtel-self.yaml, but the config keys are kubernetes and parqtel) and are activated through [alerts.presets]. Activation is insert-if-absent, so your own rules always win. Configure with mode (auto, all, or off; default auto), plus include and exclude. Conflicts between include and exclude resolve in favour of include, with a warning.
  • Live MCP tools. The Parqtel MCP server now serves real data through its tools — PromQL queries (instant, absolute range, or a trailing window), label discovery, logs, ingest rates, alerts, noise statistics, and topology. It also implements the spec-compliant Streamable HTTP transport (POST/GET/DELETE on /mcp), with the legacy /tools/* routes retained as deprecated aliases.
  • Rebuilt Overview console. The Overview pane is organised around live signal rollups: per-signal rate cards plus storage and ingest-volume charts.
  • Self-telemetry over OTLP. Parqtel can export its own traces and service-level metrics — HTTP golden signals, ingest throughput, flush duration and row counts, buffer saturation, and RSS high-water mark — and exposes CPU profiling endpoints. Configured through the telemetry settings; the parqtel-self preset pack alerts on this data.

Fixed#

IssueImpact and resolution
Series counts and result limits were wrong for composed queriesquery.max_series and query.max_samples_per_series were silently ignored for nested range selectors and most composed PromQL. Both query engines now report the same series count under the same configured memory bound.
min() returned the wrong valueThe fold was re-evaluated to produce the value it had just computed.
Label-value autocomplete missed recent data/api/v1/label/<name>/values now includes series still in the in-memory buffer.
gRPC and HTTP disagreed on batch sizeA batch that succeeded over HTTP could fail over gRPC with an opaque ResourceExhausted error. gRPC message limits are now derived from ingest.max_body_size, so the two transports cannot disagree.
Alerts used a fixed evaluation windowAlerts evaluated over a hardcoded 300-second window instead of query.lookback_delta_ns — the same window you see in the UI.
Documented environment-variable spelling had no effectThe PARQTEL__SECTION__KEY form was silently ignored because of a prefix-parsing bug. The double-underscore form now works; the single-underscore form still does too.
MCP label matchers rejected dotted label namesDotted label names failed through the percent-encoded path segment.
Metrics UI timeline was inaccurateCorrected.

Configuration#

New options in this release:

OptionPurpose

Validation now rejects a row_group_size of 0 or one greater than max_rows_per_block — a combination that silently disabled row-group pruning and degraded query performance without any error.

Security#

  • Removed vulnerable transitive dependencies from the profiling feature.
  • Added CodeQL analysis to continuous integration.

v0.2.0 — Initial public beta#

The release where the durability story landed.

Durability#

  • Write-ahead log, on by default. Bounds crash loss to ingest.wal_sync_interval_ms (1 second) rather than the whole block window (2 hours by default). A torn record from a crash mid-append is detected by per-record checksum and truncated on replay.
  • Durable index before commit. A flush now waits for the block index to be durable before committing the write-ahead log, and fails safe on timeout by leaving the log uncommitted. Without this, a crash could leave acknowledged data on disk but absent from the index — and already marked as recovered.
  • Self-healing block index. At startup the index is reconciled against the data directory in both directions: unknown block files are adopted, and entries whose file has disappeared are dropped.
  • Background flushing. A request that crosses the block row cap is acknowledged once the write-ahead log has its rows rather than after the encode completes. This requires the write-ahead log; with ingest.wal_enabled = false the background worker refuses to start and flushing stays synchronous.
  • Sharded metrics ingest. Unrelated metrics ingest concurrently while a flush encodes, with per-shard log order matching writer order.

Performance#

Correction (v0.3.1 docs): an earlier draft of these notes claimed compaction had been extended to trace blocks. The compactor supports traces, but the shipped server starts compaction for metrics and logs only — see Storage Model and Troubleshooting. Trace blocks therefore still accumulate until retention removes them.

Fixed#

IssueImpact and resolution
Credentials in arrays reached the MCP audit log in clear textParameter sanitisation now recurses into arrays and objects uniformly, and the sensitive-key list covers authorization, auth, session, cookie, and private.
Kubernetes readiness probe checked nothing/health is a static success and was wired to liveness, readiness, and startup, so a pod was marked ready while its storage was failing. /ready was added and now reads block-index metadata; point readiness at it.
Oversized ingest batches lost half their dataA batch larger than the block cap was rejected after part of it had been accepted. It is now split across blocks and ingested in full.
ingest.max_body_size was not honouredA lower framework default silently won, so raising the limit changed nothing and large batches failed with an unexplained 413.
Compaction discarded the label-value indexMerged blocks were written with an empty dictionary, degrading label-value autocomplete on every compaction pass.
Query series selector routingA selector matching more than one metric name could be routed incorrectly.
Trace block index was not persistedTrace block index metadata was not persisted like other signals.

Observability#

New self-monitoring metrics: parqtel_ingest_lock_wait_seconds, parqtel_flush_duration_seconds, parqtel_flush_inflight, parqtel_flush_rows_total, parqtel_index_lock_wait_seconds, parqtel_index_sidecar_bytes, parqtel_index_pending_writes, and parqtel_ingest_rotator_shards.

Compatibility and upgrade notes#

ConcernGuidance
On-disk formatStable from v0.2.0 onward. Pre-v0.2.0 (arrow2-era) blocks require a data-directory wipe.
Rolling backSafe within the current format — blocks are self-describing Parquet and older binaries read them.
Configuration keysAdditive. Keys are not renamed within a major series; defaults may change (as ingest.wal_enabled did in v0.3.1).
Helm chart valuesProbe defaults reproduce pre-v0.3.1 behaviour exactly, so upgrading the chart changes nothing until you edit values.
DeprecationsThe MCP legacy /tools/* routes are deprecated aliases for the Streamable HTTP transport at /mcp.
