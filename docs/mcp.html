MCP Servers#

Parqtel ships seven Model Context Protocol servers that let an LLM agent query your telemetry directly. One — parqtel-mcp-parqtel — is fully functional. The other six declare their tool surface but are not yet wired to their providers.

⚠

⚠ Security first. MCP servers have no authentication of any kind and bind 0.0.0.0 by default. They also mount no CORS, auth, or TLS middleware. Put them behind an authenticated boundary before exposing them, and do not rely on the rate limiter for access control.

Current status, stated plainly#

Of the 30 registered tools across all seven servers, 7 have live executors — all 7 in parqtel-mcp-parqtel.

The Slack, PagerDuty, Jira, Notion, Discord, and Google Docs servers register tool metadata only: the tools appear in tools/list with correct schemas, but calling one returns an echo of the parameters instead of performing the action. Their declared provider credentials are not read by any code path, so setting SLACK_BOT_TOKEN and similar has no effect today.

Treat them as declared interfaces awaiting implementation, not working integrations.

parqtel-mcp-parqtel — LIVE#

The functional server. It talks to a running Parqtel instance over the HTTP API and exposes read-oriented observability tools to an LLM agent.

Configuration#

export PARQTEL_API_URL="http://127.0.0.1:8080"
parqtel-mcp-parqtel

Tools#

ToolReturns
query_metricsParQL metric query results with time range and step
query_metrics_labelsLabel names and values, with an optional metric filter
query_logsParqtelQL log search with time range and limit

Call it#

# List tools
curl -X POST http://localhost:3007/mcp \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'

# Call a tool
curl -X POST http://localhost:3007/mcp \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{
    "jsonrpc": "2.0",
    "id": 2,
    "method": "tools/call",
    "params": {
      "name": "query_metrics",
      "arguments": {
        "query": "sum by (service) (rate(http_requests_total[5m]))",
        "start": "2026-10-06T09:00:00Z",
        "end": "2026-10-06T10:00:00Z",
        "step": "60"
      }
    }
  }'

This server is read-only against Parqtel's HTTP API — and that API is itself unauthenticated, so treat the MCP server as an unauthenticated read surface.

Integration servers (metadata only)#

These declare the intended tool surface. Schemas are complete and discovery works; execution is not implemented.

Credentials the chart and Compose file expect — SLACK_BOT_TOKEN, PAGERDUTY_API_KEY, JIRA_API_TOKEN, NOTION_API_KEY, DISCORD_BOT_TOKEN — are declared in deployment manifests but are not read by any code path.

⚠

⚠ Do not put real credentials in the Helm chart yet. The chart declares mcp.<name>.secretName, but the templates render referenced secrets as plaintext literal environment variables — never via secretKeyRef. Avoid this path for production credentials until that is fixed, even once the executors land.

Transport#

Streamable HTTP only, per MCP specification version 2025-06-18. There is no stdio transport.

MethodRouteStatus
POST/mcpJSON-RPC over Streamable HTTP
GET/mcpServer-to-client event stream
DELETE/mcpTerminate the session
GET/tools/listDeprecated alias
POST/tools/callDeprecated alias
GET/healthLiveness only — no readiness endpoint

MCP servers expose /health but not /ready. The chart's readiness probe was deliberately pointed away from them for this reason.

⚠

⚠ Send an explicit protocol version header. When a client sends no version, the JSON body falls back to 2025-06-18 but the MCP-Protocol-Version header falls back to 2024-11-05 — so the client sees two different versions in a single exchange. Also note that serverInfo.name is parqtel-mcp for all seven servers, so it does not identify which one answered.

Tool registry and rate limiting#

The tool registry holds tool metadata alongside a lookup table of executors. Discovery is a linear scan; dispatch is a hash lookup. There is no middleware layer and no per-tool policy.

Rate limiting uses a token bucket keyed by client identifier, refilling on a millisecond clock and starting full — so an immediate full burst is always permitted. Three caveats:

CaveatImpact
The limit is global, not per-toolOne chatty tool starves the others.
The client identifier comes from an unauthenticated request fieldThe limit is trivially bypassed, and the client-id map grows without bound.
The routes disagree on throttlingPOST /mcp returns 500 with JSON-RPC code -32000; the deprecated POST /tools/call returns 429 with no Retry-After.

Because of these, the rate limiter is not an access control mechanism.

Credential redaction#

Before tool arguments reach the audit log, they pass through a sanitiser that replaces the value of any key whose lowercased name contains one of:

token · api_key · password · secret · authorization
auth · session · cookie · private

The replacement is ***REDACTED***. Recursion handles objects and arrays uniformly — a fix for a regression where an array of objects such as [{"token": "…"}] was logged verbatim.

Four properties to know before relying on it:

PropertyDetail
Arguments onlyTool results are never redacted.
Audit log onlyIt is not an input filter. It does not change what is sent anywhere; only what is written down.
Unbounded nesting depthThere is no recursion cap.
Substring matching over-triggersBecause it matches anywhere in the key, innocuous fields named routing_key, keywords, author, or oauth are redacted too.

This affects tools/call on all seven servers. No Parqtel HTTP endpoint is affected.

Deploying#

# Docker Compose — MCP services are commented out by default.
# Add tokens to .env and uncomment the services you need.
docker compose up -d parqtel-mcp-parqtel

# Helm — each server is its own deployment.
helm install parqtel charts/parqtel -f charts/parqtel/ci/full-values.yaml \
  --set mcp.parqtel.enabled=true

Production checklist:

  • [ ] Put the MCP server behind an authenticated reverse proxy or service mesh
  • [ ] Restrict it with a NetworkPolicy — the port should not be publicly reachable
  • [ ] Bind to a non-default interface (MCP_HOST) where possible
  • [ ] Do not place real provider credentials in the chart while the plaintext rendering issue stands
  • [ ] Remember the Parqtel instance it points at is itself unauthenticated
