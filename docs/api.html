HTTP API Reference#

The complete endpoint surface: OTLP ingestion, Prometheus-compatible queries, log and trace search, alerting, Grafana integration, and operations.

⚠

⚠ No authentication. Every endpoint below — including ingestion and the OTLP gRPC port — is unauthenticated, and CORS is open to any origin. Do not expose ports 8080 or 4317 publicly. Put a reverse proxy or service mesh in front that terminates TLS and authenticates. The embedded console at /ui carries the same privileges as the API.

Request routing#

Error envelopes are not uniform across route groups, which matters if you are writing a client:

Route groupError shape
Prometheus-compatible routes{ "status": …, "errorType": …, "error": … }
Other Parqtel routes{ "status": …, "error": … }
Alert routes{ "error": … } — no status field
Grafana SimpleJSONSwallows errors and returns 200 []

Prerequisites#

  • Parqtel running. See the Quickstart.
  • curl for the examples below.

Ingestion (OTLP)#

Metrics and logs accept protobuf or OTLP/JSON. The bare paths content-negotiate on Content-Type; the /json variants accept OTLP/JSON directly. Traces are different: /v1/traces and /v1/traces/json both decode OTLP/JSON only — the HTTP trace path does not accept protobuf. All three signals are also accepted over OTLP gRPC on port 4317 through an identical decode path, which is the recommended transport for traces.

MethodEndpointDescription
POST/v1/metricsIngest metrics (protobuf or JSON)
POST/v1/metrics/jsonIngest metrics (OTLP/JSON)
POST/v1/logsIngest logs (protobuf or JSON)
POST/v1/logs/jsonIngest logs (OTLP/JSON)
POST/v1/tracesIngest spans (OTLP/JSON only)
POST/v1/traces/jsonIngest spans (OTLP/JSON)
curl -X POST http://localhost:8080/v1/metrics/json \
  -H "Content-Type: application/json" \
  -d '{
  "resourceMetrics": [{
    "resource": {"attributes": [
      {"key": "service.name", "value": {"stringValue": "demo"}}]},
    "scopeMetrics": [{"metrics": [{
      "name": "http_requests_total",
      "gauge": {"dataPoints": [{
        "asDouble": 42,
        "timeUnixNano": "'$(date +%s%N)'",
        "attributes": [{"key": "method", "value": {"stringValue": "GET"}}]}]}}]}]}]}'
BehaviourDetail
Body limitingest.max_body_size (default 10 MB), applied consistently to HTTP and used to derive gRPC message limits.
Oversized batchesSplit across blocks, not rejected.
AcknowledgementReturned once the row is in the write-ahead log, not once the block is on disk.
Span side effectServer-kind spans derive traces_service_requests_total, traces_service_errors_total, and traces_service_duration_ms gauge samples (one per span).
↗

In OTLP/JSON, attributes must be an array of {"key": …, "value": {"stringValue": …}} objects. A plain object map is rejected.

MethodEndpointParameters
GET/api/v1/queryquery (required), time (optional)

Logs#

Filter grammar: ParqtelQL.

MethodEndpointParameters
GET/api/v1/logsquery, start, end (required) · limit · order · severity_min · search
GET/v1/logs/countquery, start, end
GET/v1/logs/fields— returns dedicated columns and common attributes
GET/v1/logs/field_valuesfield_name, limit, q (prefix)
curl "http://localhost:8080/api/v1/logs?query=severity%3E%3DERROR&start=1700000000&end=1700003600&limit=100"

The query grammar is ParqtelQL — bare terms, field=value, severity>=WARN, ranges, -exclusion, and boolean AND/OR/NOT. See Query Reference.

Traces & correlation#

MethodEndpointParameters
GET/v1/traces/searchstart, end, trace_id, q, limit (default 200, max 10,000)
GET/v1/correlateanchor_signal, anchor_timestamp_ns, anchor_labels (JSON), target_signal, window_ns (default 5s), limit (default 50)

Trace search returns spans, each carrying its trace_id for client-side grouping. Span predicates (q) are pushed down into the scan before the result cap, so a filter never loses matches to truncation.

curl "http://localhost:8080/v1/traces/search?q=service.name%3D%22my-web-app%22&limit=20"

curl -G "http://localhost:8080/v1/correlate" \
  --data-urlencode "anchor_signal=traces" \
  --data-urlencode "anchor_timestamp_ns=$(date +%s%N)" \
  --data-urlencode 'anchor_labels={"trace_id":"5b8efff798038103d269b633813fc60c"}' \
  --data-urlencode "target_signal=log"
⚠

⚠ Parameter caveats for /v1/traces/search. Only trace_id and q are honoured. service, operation, min_duration_ms, and max_duration_ms are accepted by the published specification but ignored by the running server. Filter with q instead. For /v1/correlate, target_signal is compared against the singular names "metric" and "log", not the plural forms the specification lists.

Pipelines & saved searches#

⚠

⚠ Stored, not executed. /api/v1/pipelines and /api/v1/recording_rules validate and persist definitions, but v0.3.1 wires no ingest-stage processor and no ruler scheduler, so these definitions have no effect on data or queries yet. /v1/search (the staged PQL pipeline query) is executed and is unrelated to those definitions.

MethodEndpointDescription
POST/v1/searchRun a ParqtelQL pipeline query over all three signals
GET/api/v1/pipelinesList pipeline definitions (stored only)
POST/api/v1/pipelinesCreate a pipeline definition (stored only)
DELETE/api/v1/pipelines/{name}Delete a pipeline definition
GET/api/v1/recording_rulesList recording-rule groups (stored only)
POST/api/v1/recording_rulesCreate a recording-rule group (stored only)
DELETE/api/v1/recording_rules/{name}Delete a recording-rule group
GET/api/v1/saved_searchesList saved searches
POST/api/v1/saved_searchesSave a search
DELETE/api/v1/saved_searches/{id}Delete a saved search
curl -X POST http://localhost:8080/v1/search \
  -H "Content-Type: application/json" \
  -d '{
    "query": "fetch logs | filter severity>=ERROR | correlate traces window=2s",
    "start": 1700000000,
    "end": 1700003600
  }'

GET/api/v1/alerts/{id}Get one alert ({id} is a ULID)
POST/api/v1/alerts/{id}/acknowledgeAcknowledge (JSON body, optional by)
POST/api/v1/alerts/{id}/resolveResolve (JSON body, optional by)
GET/api/v1/rulesList alert rules
POST/api/v1/rulesCreate an alert rule at runtime
PUT/api/v1/rules/{id}Replace an alert rule
DELETE/api/v1/rules/{id}Delete an alert rule
GET/api/v1/alerts/routesList notification routes
POST/api/v1/alerts/routesSet notification routes
GET/api/v1/alerts/silencesList silences
POST/api/v1/alerts/silencesCreate a silence
DELETE/api/v1/alerts/silences/{name}Delete a silence

One alert instance is created per result series, fingerprinted by rule id plus the series labels. Alert instance id values are ULIDs generated by the store, different from the rule id.

↗

The evaluator thresholds the newest raw sample of each series. In v0.3.1 rate(), aggregations, and histogram_quantile() are not applied to the thresholded value; see Alerting.

curl -s http://localhost:8080/api/v1/alerts | jq '.data[] | {id, rule_id, state, severity}'

curl -X POST http://localhost:8080/api/v1/alerts/<ulid>/acknowledge \
  -H "Content-Type: application/json" -d '{"by":"oncall@example.com"}'

curl -X DELETE http://localhost:8080/api/v1/alerts/silences/maintenance-2026-10-05

Operations#

MethodEndpointDescription
GET/healthLiveness. Static success.
GET/readyReadiness. Reads block-index metadata; returns 503 when storage is unusable.
GET/metricsPrometheus metrics.
GET/api/v1/statsStorage, buffer, and config snapshot per signal.
GET/api/v1/ingest_ratesLive per-signal rates: current, 60s/5m/15m averages, gap_secs spike/gap detection, and a per-second sparkline via history_secs (default 180, max 900).
GET/oasThe OpenAPI 3.0 specification.
GET/uiThe embedded console.
GET/Redirects to /ui.
GET/debug/pprof/memoryMemory decomposition. Requires telemetry.profiling_enabled.
GET/debug/pprof/summaryTop CPU frames over a window.
GET/debug/pprof/profileCPU profile (protobuf, for go tool pprof).

Profiling is gated by telemetry.profiling_enabled (endpoints return 404 while disabled) and serialized by a process-wide lock — a second capture while one runs returns 429.

↗

The published OpenAPI specification is not authoritative — it is generated alongside the code and is known to diverge from the running server. Treat this page and a live instance as the source of truth. See Internals for details.

Metrics worth alerting on#

Scrape /metrics and alert on these:

parqtel_process_rss_bytes              # resident memory (the dominant sizing risk)
parqtel_process_rss_hwm_bytes          # high-water mark
parqtel_buffer_points / _logs / _spans # buffered points per signal
parqtel_ingested_points_total          # accepted points
parqtel_ingest_errors_total            # rejected batches
parqtel_ingest_lock_wait_seconds       # rotator contention → raise rotator_shards
parqtel_flush_duration_seconds         # Parquet encode time
parqtel_flush_inflight                 # background flush worker saturation
parqtel_flush_rows_total               # rows per flush, per signal
parqtel_index_sidecar_bytes            # index.json size, per signal
parqtel_index_pending_writes           # mutations queued for the next sidecar write
parqtel_storage_blocks / _bytes / _rows # per signal
parqtel_query_duration_seconds         # query latency
parqtel_query_errors_total             # query failures
parqtel_ingest_gap_secs                # silence/gap detection

Full guidance: Troubleshooting.

Errors and limits#

StatusWhen
400Malformed OTLP, invalid query, or a predicate parse error.
404Unknown route, or a /debug/pprof/* endpoint while profiling is disabled.
413Request body exceeds ingest.max_body_size.
408Request exceeded the query.timeout_secs middleware timeout — applied to every route, ingestion included.
429A profiling capture is already in progress.
500Internal error, including a write-ahead log append failure. The write is not acknowledged.
503Readiness check failed (/ready only).

Middleware applied to all routes: CORS (any origin), HTTP tracing, a request timeout of query.timeout_secs, and body limits from ingest.max_body_size applied twice — the framework default and an explicit request-body-limit layer — so the configured value is authoritative.

Troubleshooting#

SymptomCauseResolution
400 on an OTLP/JSON postattributes sent as an object rather than an array.Use [{"key": …, "value": {"stringValue": …}}].
413 on a large batchBatch exceeds ingest.max_body_size.Raise the limit, or reduce send_batch_size at your exporter.
408 on a slow queryExceeded query.timeout_secs.Narrow the range or raise the timeout.
Query returns fewer series than expectedSilent truncation at query.max_series.Compare totalSeriesCount with returned series.
Instant query returns nothing for recent dataTimestamp outside the 5-minute lookback.Use /api/v1/query_range.
/v1/traces/search ignores service=Those parameters are accepted but not honoured.Filter with q instead.
/v1/correlate finds nothingWrong target_signal form.Use the singular metric or log.
Grafana shows an error but the API is fineSimpleJSON swallows errors and returns 200 [].Check Parqtel logs; query the API directly to see the real error.
404 on /debug/pprof/*Profiling is disabled.Set telemetry.profiling_enabled = true.
429 from a profiling endpointA capture is already running.Wait for it to finish; captures are serialized.
