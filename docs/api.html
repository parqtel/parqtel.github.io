API Reference

Parqtel exposes a Prometheus-compatible HTTP API, OTLP ingestion over HTTP and gRPC, Grafana SimpleJSON, a full alerting surface and a set of operations endpoints.

↗

Prefer an interactive view? Open the API Explorer — search and expand every operation straight from the OpenAPI spec. The spec is also served live at /oas.

⚠

There is no authentication. Every endpoint below — including ingestion and the OTLP gRPC port — is unauthenticated, and CORS is open to any origin. Do not expose ports 8080 or 4317 publicly. Put a reverse proxy or service mesh in front that terminates TLS and authenticates. The embedded console reads and writes with the same privileges as the API.

Ingestion (OTLP)

All ingest endpoints accept protobuf or OTLP/JSON. The bare paths content-negotiate on Content-Type; the /json variants accept OTLP/JSON directly. The same payloads are also accepted over OTLP gRPC on :4317 (tonic, all three collector services) through an identical decode path.

MethodEndpointDescription
POST/v1/metricsIngest metrics (protobuf or JSON)
POST/v1/metrics/jsonIngest metrics (OTLP/JSON)
POST/v1/logsIngest logs (protobuf or JSON)
POST/v1/logs/jsonIngest logs (OTLP/JSON)
POST/v1/tracesIngest spans
POST/v1/traces/jsonIngest spans (OTLP/JSON)
 
curl -X POST http://localhost:8080/v1/metrics/json \
-H "Content-Type: application/json" \
-d '{"resourceMetrics":[{"resource":{"attributes":[
{"key":"service.name","value":{"stringValue":"demo"}}]},
"scopeMetrics":[{"metrics":[{"name":"http_requests_total",
"gauge":{"dataPoints":[{"asDouble":42,
"timeUnixNano":"1700000000000000000",
"attributes":[{"key":"method","value":{"stringValue":"GET"}}]}]}}]}]}]}'
  • Body limit ingest.max_body_size (default 10 MB), applied consistently to HTTP and used to derive gRPC message limits. Oversized batches are split across blocks, not rejected.
  • A write is acknowledged once the row is in the write-ahead log, not once the block is on disk — see Durability & recovery.
  • Server-kind spans additionally derive traces_service_{requests,errors,duration_ms}_total metrics.

Traces & correlation

MethodEndpointParameters
GET/v1/traces/searchstart, end, trace_id, q, limit (default 200, max 10 000)
GET/v1/correlateanchor_signal, anchor_timestamp_ns, anchor_labels (JSON), target_signal, window_ns (default 5 s), limit (default 50)

Trace search returns spans, each carrying its trace_id for client-side grouping. Span predicates (q) are pushed down into the scan, before the result cap, so a filter never loses matches to truncation.

⚠

Two known spec/code mismatches in this area, which also exist in openapi.yaml: the published spec documents service, operation, min_duration_ms and max_duration_ms for /v1/traces/search, but the handler ignores all four — only trace_id and q are honoured. And target_signal is compared as the singular "metric" / "log", not the plural forms the spec lists. Filter spans with q and pass singular signal names to correlate.

Errors and limits

StatusWhen
400Malformed OTLP, invalid query, or a predicate parse error.
404Unknown route, or a /debug/pprof/* endpoint while profiling is disabled.
413Request body exceeds ingest.max_body_size.
408Request exceeded the query.timeout_secs middleware timeout — applied to every route, ingest included.
429A profiling capture is already in progress — captures are serialized by a process-wide lock.
500Internal error — including a WAL append failure. The write is not acknowledged.
503Readiness check failed (/ready only).

Middleware: CORS (any origin), HTTP tracing, a request timeout of query.timeout_secs, and body limits of ingest.max_body_size applied twice — axum's default limit and a request-body-limit layer — so the configured value is authoritative. Error envelopes are not uniform: Prometheus routes return {status, errorType, error}, Parqtel routes {status, error}, alert routes {error} with no status, and Grafana SimpleJSON swallows errors and returns 200 [].

⚠

Result limits truncate silently. Exceeding query.max_series or query.max_samples_per_series produces no error and no status code — the response is simply shorter. Detect it client-side from totalSeriesCount (the pre-truncation match count) and volume_summary. Logs and traces do carry explicit truncated booleans. Also note the two engine paths keep different samples when truncating: the AST path keeps the oldest N, the legacy plan path keeps the first N in scan order.

OpenAPI spec accuracy

The spec at /oas is broadly useful but is not authoritative. Known divergences, in rough severity order:

  • /v1/logs/field_values documents the parameter as field; the handler reads field_name. A documented call returns values for the empty field.
  • /v1/traces/search documents service, operation, min_duration_ms, max_duration_ms — all four are ignored.
  • /v1/traces is documented as accepting protobuf, but the route serves the JSON handler with no content negotiation (unlike /v1/metrics and /v1/logs).
  • /api/v1/rules POST/PUT is documented as application/json; the body is a raw string parsed as YAML.
  • /v1/correlate: documented window_ns default is 300 s, the code uses 5 s; target_signal is documented as plural but compared as singular.
  • /api/v1/logs limit is documented with default 100; the code uses 1000.
  • 15 routes are missing from the spec entirely, including /, /ui, /oas, /debug/pprof/*, /v1/search, /api/v1/saved_searches (×3), /api/v1/alerts/routes and /api/v1/alerts/silences (×2).
  • The spec's info.version still reads 0.1.0 and does not track releases.

The table at the top of this page is derived from the router in source, not from the spec.
