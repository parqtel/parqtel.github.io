FAQ & Glossary

Common questions about Parqtel, plus the terms used throughout the docs. Reflects v0.3.1 (5 Oct 2026).

What is Parqtel?

A single-binary, Rust-based observability backend. It ingests OpenTelemetry metrics, logs and traces — over HTTP or gRPC — stores them as compressed Apache Parquet, and serves a Prometheus-compatible query API with an embedded console.

How does it compare to Prometheus / Loki / VictoriaMetrics?

Parqtel is complementary: point Grafana at it as a long-term, low-cost store while keeping your real-time stack.

If the process crashes, do I lose data?

Not the acknowledged part. Every decoded value is appended to a write-ahead log before its HTTP request is acknowledged, and the commit point only advances after the block file is renamed into place and the block index is durable. On startup Parqtel replays whatever the log did not flush, before it starts listening.

Two caveats worth internalising:

  • With the default wal_sync_mode = "interval" and wal_sync_interval_ms = 1000, a machine crash (not a process crash) can lose up to one sync interval. Set wal_sync_mode = "always" to bound it to the last unacknowledged write, at a throughput cost.
  • wal_enabled = false removes this protection entirely — a crash then loses a whole block window. The binary and chart defaults are both true; only the local Compose dev profile disables it.

Full protocol: Durability & recovery.

Is it production ready?

The engine is built for production constraints: no unsafe code, clippy-denied panics, crash-safe Parquet writes, self-healing index reconciliation, graceful shutdown, and a supply chain that is Trivy-scanned, cosign-signed and provenance-attested.

Two limitations are documented rather than hidden: there is no authentication, and the in-memory buffer is unbounded. See Known issues.

Does it support tracing?

Yes. Traces ingest over OTLP (/v1/traces, or the gRPC service) and browse in the built-in console with a waterfall. Two things make traces more useful here than a plain store:

  • Zero-config RED. Server-kind spans automatically derive traces_service_{requests,errors,duration_ms}_total per service and operation.
  • Tail sampling keeps errors and slow traces while dropping a fraction of healthy ones — hashed on trace_id, so whole traces live or die together. The default keeps everything.

Traces reuse the [storage] configuration — there is no separate trace block.

Is there authentication?

No. There is no API key, no bearer token, no X-API-Key header and no auth middleware anywhere in the server. CORS is open to any origin. Every endpoint — including ingestion and the OTLP gRPC port — is fully open, and the embedded console carries the same privileges as the API.

Terminate TLS and authenticate at a reverse proxy or service mesh. The optional /debug/pprof/* endpoints are disabled by default for exactly this reason. More: Known issues.

How do I back up Parqtel?

Blocks are immutable once written, so they can be copied or snapshotted while the server runs. Back up index.json for fast startup — but a lost or stale sidecar repairs itself at startup through reconciliation, so it is an optimisation rather than a requirement. WAL segments are ephemeral: a replay is a replay, not a backup.

Why did my query return fewer results than I asked for?

Result limits truncate silently. Exceeding query.max_series (1000) or query.max_samples_per_series (10 000) produces no error and no status code — just a shorter response. Compare totalSeriesCount against the series returned to detect it. See Result limits.

What do I need for MCP?

Run a parqtel-mcp-* binary; it speaks Streamable HTTP on POST /mcp. For parqtel-mcp-parqtel, set PARQTEL_API_URL and you are done — its 7 tools are live.

The Slack, PagerDuty, Jira, Notion, Discord and Google Docs servers currently register tool metadata only: they appear in tools/list but calling them does not perform the action, and their provider credentials are not read. See MCP servers.

Can I upgrade from an older release?

Within the current on-disk format, yes — blocks stay readable and rolling back is safe. Across the arrow2 → arrow 59 migration the encoding changed and blocks written by arrow2-era builds are unreadable, so that boundary requires wiping the data directory. See Release notes.

What licence?

Apache-2.0.

Glossary

TermMeaning
OTLPOpenTelemetry Protocol — the wire format for metrics, logs and traces, over HTTP or gRPC.
BlockA self-contained, immutable Parquet file covering a fixed time window (2 h metrics, 30 min logs).
Row groupA horizontal slice of a Parquet block carrying min/max statistics — the basis of row-group pruning.
Pruning chainThe five levels a query uses to discard irrelevant blocks, row groups and columns before decoding anything.
ProjectionReading only the columns a query needs. Metrics reads 7 of 15; logs and traces are not projected yet.
Sidecarindex.json — the block metadata index kept beside the blocks, and the only index file.
ReconciliationThe startup pass that adopts unknown block files into the index and drops entries whose files have gone.
WALWrite-ahead log. Acknowledged writes land here before blocks are written; see Durability.
Commit pointThe WAL position up to which data is known to be in a durable block. Segments below it are deleted.
CompactionMerging small blocks into larger ones to cut file count and scan fan-out.
RetentionTime-to-live per signal; expired blocks are deleted. The block index is not bounded by retention.
Memory bufferThe in-memory store that makes the most recent data queryable before its block is flushed.
ParQLParqtel's PromQL-compatible metrics query language.
ParqtelQLThe lenient boolean filter language for logs and spans.
PQL pipelineA staged query over all three signals — fetch | filter | parse | stats | correlate.
RED bridgeAutomatic derivation of request/error/duration metrics from server-kind spans.
Tail samplingKeeping errors, slow traces and a deterministic fraction of the rest.
Recording ruleA PromQL expression evaluated on a schedule and written back as a new series.
MCPModel Context Protocol — a JSON-RPC standard letting LLMs call external tools.
SimpleJSONGrafana datasource plugin protocol that Parqtel implements.
