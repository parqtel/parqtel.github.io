FAQ & Glossary#

Answers to the questions that come up most often when evaluating or operating Parqtel, followed by a glossary of the terms used throughout these docs.

This page reflects release v0.3.1 (5 October 2026).

Product & positioning#

What is Parqtel?#

A single-binary observability backend. It ingests OpenTelemetry metrics, logs, and traces over HTTP or gRPC, stores them as compressed Apache Parquet, and serves a Prometheus-compatible query API with an embedded web console. See the Overview for the full picture.

How does it compare to Prometheus, Loki, or VictoriaMetrics?#

DimensionParqtelTraditional time-series databases
StorageColumnar Parquet, typically 10–20× compressionPurpose-built time-series or LSM storage
Footprint~15 MB scratch image, no external storeOften larger; may need sidecars or stateful sets
SignalsMetrics + logs + traces in one engineUsually separate systems per signal
QueryPromQL-compatible — 91 functions, 12 aggregations, with documented divergencesFull PromQL
DurabilityWrite-ahead log; acknowledged writes survive a process crashVaries
Best atCheap, long-lived, edge and archival telemetryLow-latency real-time alerting at scale

Parqtel is complementary, not necessarily a replacement: point Grafana at it as a long-term, low-cost store while keeping your real-time stack for the live window. See Use Cases & Comparisons for scenario-by-scenario guidance.

Is it production ready?#

The engine is built for production constraints: no unsafe code, crash-safe Parquet writes, self-healing index reconciliation, graceful shutdown, and a signed, scanned supply chain.

Two limitations are documented rather than hidden — there is no authentication, and the in-memory buffer is unbounded. Both are covered in Troubleshooting.

What licence?#

Apache-2.0.

Operations & reliability#

If the process crashes, do I lose data?#

Not the acknowledged part. Every decoded value is appended to the write-ahead log before its HTTP request is acknowledged, and the commit point only advances after the block file is renamed into place and the block index is durable. On startup, Parqtel replays whatever the log did not flush — before it starts listening.

Two caveats are worth internalising:

ScenarioData at risk
Process crash (default settings)None. Acknowledged writes are in the write-ahead log and are replayed.
Machine crash with wal_sync_mode = "interval" and wal_sync_interval_ms = 1000Up to one sync interval (1 second). Set wal_sync_mode = "always" to bound this to the last unacknowledged write, at a throughput cost.
Any crash with wal_enabled = falseA whole block window (2 hours for metrics by default).

The binary and chart defaults both enable the write-ahead log. Only the local Docker Compose development profile disables it.

Full protocol: Durability & Recovery.

How do I back up Parqtel?#

Blocks are immutable once written, so they can be copied or snapshotted while the server runs. Back up the index sidecar for faster startup — but a lost or stale sidecar repairs itself at startup through reconciliation, so it is an optimisation rather than a requirement.

Write-ahead log segments are ephemeral: a replay is a replay, not a backup.

Full procedure: Back Up, Restore & Upgrade.

Is there authentication?#

No. There is no API key, no bearer token, no X-API-Key header, and no authentication middleware. CORS is open to any origin. Every endpoint — including ingestion and the OTLP gRPC port — is fully open, and the embedded console carries the same privileges as the API.

Terminate TLS and authenticate at a reverse proxy or service mesh. The optional profiling endpoints are disabled by default for exactly this reason.

Can I upgrade from an older release?#

Within the current on-disk format, yes — blocks stay readable and rolling back is safe. Across the storage-encoding migration (the arrow2 → arrow 59 change) the Parquet encoding itself changed, so blocks written by arrow2-era builds are unreadable and that boundary requires wiping the data directory.

Details: Back Up, Restore & Upgrade and Release Notes.

Querying#

Why did my query return fewer results than I asked for?#

Result limits truncate silently. Exceeding query.max_series (1000) or query.max_samples_per_series (10,000) produces no error and no status code — just a shorter response.

Compare totalSeriesCount against the number of series actually returned to detect truncation. See Query Reference — Result limits.

Why is a metric I just sent missing from an instant query?#

An instant query only looks back 5 minutes (query.lookback_delta_ns), which matches Prometheus behaviour. A data point timestamped outside that window is not returned by an instant query — use a range query instead.

Signals & integrations#

Does it support tracing?#

Yes. Traces ingest over OTLP (the gRPC service, or /v1/traces over HTTP/JSON — note the HTTP trace path is JSON-only) and browse in the built-in console with a waterfall view. Two things make traces more useful here than in a plain store:

  • Zero-config RED metrics. Server-kind spans automatically derive traces_service_requests_total, traces_service_errors_total, and traces_service_duration_ms per service and operation, so service dashboards work without hand-written instrumentation. The bridge writes one gauge sample per span, so use _over_time functions rather than rate().
  • Tail sampling keeps errors and slow traces while dropping a fraction of healthy ones — hashed on trace_id, so whole traces live or die together. The default keeps everything.

Traces reuse the [storage] configuration; there is no separate trace block section.

Note: trace blocks are not compacted by the shipped server. They are subject to retention and index persistence, but not compaction, so trace file count grows until retention removes expired blocks.

What do I need for MCP?#

Run a parqtel-mcp-* binary; it speaks Streamable HTTP on POST /mcp.

For the Parqtel MCP server, set PARQTEL_API_URL and you are done — its tools are live.

The Slack, PagerDuty, Jira, Notion, Discord, and Google Docs servers currently register tool metadata only: they appear in tools/list, but calling them does not perform the action and their provider credentials are not read. See MCP Servers.
